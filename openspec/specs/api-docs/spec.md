## Requirements
### Requirement: Versioned OpenAPI snapshots
The project SHALL store a frozen OpenAPI document per released API version, generated by a management command at release time and committed to the repository.

#### Scenario: Creating a snapshot
- **WHEN** a maintainer runs `manage.py api_snapshot` for the current version
- **THEN** `server/apps/apiversions/openapi/<version>.json` is written with `info.version` equal to that version

#### Scenario: Missing snapshot
- **WHEN** CI runs and the current registry version has no snapshot
- **THEN** the build fails

### Requirement: Serving schema per version
The API SHALL serve the live schema for the current version and the stored snapshot for older supported versions.

#### Scenario: Old schema requested
- **WHEN** a client requests `/v1/openapi.json?api_version=2026-12-01`
- **THEN** the stored snapshot for `2026-12-01` is returned

#### Scenario: Live schema versioning metadata
- **WHEN** a client requests `/v1/openapi.json`
- **THEN** `info.version` equals the current API version date
- **AND** the `Api-Version` header and `api_version` query parameter are documented

#### Scenario: Docs version switching
- **WHEN** a user opens the docs UI
- **THEN** every supported version is reachable and loads its matching schema

### Requirement: Contract tests against snapshots
The test suite SHALL validate responses of every supported non-current version for every operation with registered transforms against that version's snapshot schema, and SHALL include both direct-write GeoJSON operations.

#### Scenario: Broken transform
- **WHEN** a downgrade transform produces a shape that differs from the version's snapshot
- **THEN** the contract test fails

#### Scenario: Direct-write endpoint escape
- **WHEN** a direct-write GeoJSON endpoint does not apply a registered transform
- **THEN** the contract test fails
